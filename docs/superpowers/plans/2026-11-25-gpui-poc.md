# GPUI Proof of Concept Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `mise run run:gui` opens a gpui-kit window with text, a working button and a volume slider, and moving the slider shows a click-through, non-focus-stealing volume overlay above every other app on Windows.

**Architecture:** All code lives in the existing `pcpanel-gui` bin crate. `main_window.rs` is the normal app window. `overlay.rs` owns the overlay's whole lifecycle (approach A: open on demand, update while visible, remove 1.5s after the last change). `click_through.rs` holds the only Win32 code. The overlay window is a GPUI `WindowKind::PopUp` (topmost, no taskbar entry) with a transparent background, opened with `focus: false`.

**Tech Stack:** gpui-kit 0.11.0 (bundles GPUI `gpui-pre =0.3.14`, gpui-component 0.11.0), `windows` 0.62, `raw-window-handle` 0.6, CMake 4.5.1 via mise.

**Spec:** `docs/superpowers/specs/2026-11-25-gpui-poc-design.md`

## Global Constraints

- gpui-kit `0.11.0` from crates.io. Never add or override GPUI crates (`gpui-pre*`) directly.
- Setup order per the getting-started guide: `application().with_assets(assets::Assets).run(|cx| { init(cx); … open_window(…) })`. `init` runs before any window or component is created. Use `gpui_kit::open_window`, which wraps views in `Root`, and never return a `Root` yourself.
- Windows only. Don't spend effort on Linux or macOS, including making them compile.
- Every tool is pinned in the project `mise.toml`, so CMake goes there too.
- Warnings never fail the build (repo rule). Keep the `use pcpanel_core as _; use pcpanel_ipc as _;` stub lines.
- Overlay values: about 320×64 logical px, horizontally centred, bottom edge 48 px above the bottom of the primary display's visible area (above the taskbar). Hide 1500 ms after the last change. The delayed-trigger button waits 3 s.
- Don't drop click-through silently. If it can't be made to work, stop and report.

## Review Focus

1. **Rapid slider drags:** dozens of `Change` events per second must update one overlay window, never open a second one. (Task 2, Step 6)
2. **Overlay gone when the next change arrives:** if the stored overlay handle no longer refers to a live window, the next change must open a fresh overlay, not silently do nothing. (Task 2, Step 6)
3. **Closing the main window while the overlay is visible:** the app must exit, and the pending hide must not panic. (Task 2, Step 6)
4. **Display scaling at 125% or 150%:** the overlay must still sit bottom-centre above the taskbar. GPUI bounds are logical px, so don't multiply by the scale factor. (Task 2, Step 6)
5. **Levels 0 and 100:** the bar must render empty and full respectively, with no overflow past the panel. (Task 2, Step 6)

### Task 2: Volume slider and the always-on-top overlay

**Files:**
- Create: `crates/pcpanel-gui/src/overlay.rs`
- Modify: `crates/pcpanel-gui/src/main_window.rs`, `crates/pcpanel-gui/src/main.rs` (`mod overlay;`)

**Interfaces:**
- Consumes: `MainWindow` from Task 1.
- Produces:
  - `overlay::overlay_bounds(visible: Bounds<Pixels>) -> Bounds<Pixels>` (pure)
  - `overlay::VolumeOverlay`, an entity created with `cx.new(|_| VolumeOverlay::new())`, with `pub fn show(&mut self, level: f32, cx: &mut Context<Self>)`, where `level` is 0.0–100.0
  - private `OverlayView { level: f32 }`, which implements `Render`
  - constants `OVERLAY_SIZE: Size<Pixels>` (320×64), `BOTTOM_MARGIN: Pixels` (48), `HIDE_AFTER: Duration` (1500 ms)
  - Task 3 adds a call inside `VolumeOverlay`'s window-opening code.

- [ ] **Step 1: Write the failing geometry tests** in `overlay.rs` under `#[cfg(test)] mod tests`:

```rust
#[test]
fn centred_above_bottom_of_primary_display() {
    let visible = Bounds::new(point(px(0.), px(0.)), size(px(1920.), px(1040.)));
    let b = overlay_bounds(visible);
    assert_eq!(b.size, size(px(320.), px(64.)));
    assert_eq!(b.origin, point(px(800.), px(928.))); // (1920-320)/2, 1040-48-64
}

#[test]
fn respects_non_zero_display_origin() {
    let visible = Bounds::new(point(px(-1280.), px(200.)), size(px(1280.), px(984.)));
    assert_eq!(overlay_bounds(visible).origin, point(px(-800.), px(1072.)));
}
```

- [ ] **Step 2: Run them to make sure they fail.** Run `mise exec -- cargo nextest run -p pcpanel-gui`. Expected: a compile failure, because `overlay_bounds` is not defined.

- [ ] **Step 3: Implement `overlay_bounds`** from the constants above. Run the same command. Expected: 2 tests pass.

- [ ] **Step 4: Implement `VolumeOverlay`.** It holds three fields: `window: Option<AnyWindowHandle>`, `view: Option<Entity<OverlayView>>` and `hide_task: Option<Task<()>>`.
  - `show(level)`:
    1. Check the stored handle is live with `handle.update(cx, |_, _, _| ()).is_ok()`.
    2. If it's live, update `view.level` and call `cx.notify()` on the view.
    3. Otherwise, open the window with `gpui_kit::open_window` using these `WindowOptions`:
       - `kind: WindowKind::PopUp`
       - `focus: false`
       - `show: true`
       - `titlebar: None`
       - `is_movable: false`, `is_resizable: false`, `is_minimizable: false`
       - `window_background: WindowBackgroundAppearance::Transparent`
       - `window_bounds: Some(WindowBounds::Windowed(overlay_bounds(cx.primary_display()…visible_bounds())))`
       
       Then store the handle and the view.
    4. Finally, replace `hide_task` with a `cx.spawn` that awaits `cx.background_executor().timer(HIDE_AFTER)` and then calls `hide`. Replacing the field drops the previous task, and dropping a GPUI task cancels it, so no generation counter is needed.
  - `hide`: `take()` the handle and the view, then call `handle.update(cx, |_, window, _| window.remove_window())`, ignoring an `Err`, since the window may already be gone.
  - `OverlayView::render`:
    - a `size_full`, rounded, dark, slightly translucent panel with padding
    - inside it, a row with a fixed-width track (dark grey) containing a fill whose width is `relative(level / 100.0)` (light colour), and a `"{level:.0}%"` label
    - clamp `level` to 0–100 before using it

- [ ] **Step 5: Wire up the main window.**
  - `MainWindow` gains `slider: Entity<SliderState>` (from `gpui_kit::component::slider`), built as `SliderState::new().min(0.).max(100.).step(1.).default_value(50.)`, and `overlay: Entity<VolumeOverlay>`.
  - In `new`, use `cx.subscribe_in(&slider, window, …)` so that on `SliderEvent::Change(v)` it calls `overlay.update(cx, |o, cx| o.show(v.end(), cx))`. Store the `Subscription` in a `_subscriptions: Vec<Subscription>` field.
  - Render a `Slider::new(&self.slider)` inside a fixed-width (about 300 px) container, plus `Button::new("delayed").label("Show overlay in 3s")`. Its click spawns a task that waits 3 s and then shows the overlay at the slider's current value (`slider.read(cx).value().end()`). Call `.detach()` on that task.

- [ ] **Step 6: Verify by eye** (spec verification 3 and 5, plus Review Focus 1–5). Run `mise run run:gui`, then check:
  - Put a browser window partly behind the main window. Drag the slider: the overlay appears bottom-centre above both windows and tracks the value. It disappears about 1.5 s after you release.
  - Drag back and forth quickly for 5 s: only one overlay ever appears (no stacked or flickering second panel), and there's still one taskbar entry.
  - Drag to 0 and to 100: the bar is empty and full respectively, and stays inside the panel.
  - Let the overlay hide, then drag again: it reappears.
  - Drag, then immediately close the main window: the process exits with no panic in the terminal.
  - If Windows display scaling is above 100%, the overlay is still bottom-centre above the taskbar.
  - Note whether the overlay's first appearance shows a visible delay or a one-frame flash (approach A vs B). Write the observation in the commit body.

- [ ] **Step 7: Commit.**

git add crates/pcpanel-gui
git commit -m "Add volume slider and always-on-top overlay window"

### Task 3: Click-through and focus check

**Files:**
- Create: `crates/pcpanel-gui/src/click_through.rs`
- Modify: `crates/pcpanel-gui/Cargo.toml`, `crates/pcpanel-gui/src/overlay.rs`, `crates/pcpanel-gui/src/main.rs` (`#[cfg(windows)] mod click_through;`)

**Interfaces:**
- Consumes: the window-opening code in `VolumeOverlay::show` from Task 2.
- Produces: `click_through::enable(window: &Window) -> anyhow::Result<()>`, or `Result<(), String>` if `anyhow` isn't already a direct dependency (don't add a dependency only for this). It's called inside the `open_window` build closure, which receives `&mut Window`.

- [ ] **Step 1: Add the dependencies.**

```toml
[target.'cfg(windows)'.dependencies]
raw-window-handle = "0.6"
windows = { version = "0.62", features = ["Win32_Foundation", "Win32_UI_WindowsAndMessaging"] }
```

- [ ] **Step 2: Implement `enable`.**
  1. Get the native handle: `raw_window_handle::HasWindowHandle::window_handle(window)?.as_raw()`, matched on `RawWindowHandle::Win32(h)`, giving `HWND(h.hwnd.get() as *mut c_void)`.
  2. Read the extended style with `GetWindowLongPtrW(hwnd, GWL_EXSTYLE)`, OR in `WS_EX_LAYERED | WS_EX_TRANSPARENT`, and write it back with `SetWindowLongPtrW`.
  3. Call `SetLayeredWindowAttributes(hwnd, COLORREF(0), 255, LWA_ALPHA)`. A layered window without this is invisible.

  Add a `// SAFETY:` comment: the HWND comes from GPUI's live window, and we're on the UI thread. Call `enable` from the overlay's build closure. Log an `Err` to stderr; don't panic.

- [ ] **Step 3: Check that rendering survived (the risk check).** Run `mise run run:gui` and drag the slider.
  - **If the overlay renders as before:** go to Step 4.
  - **If it's invisible, black or garbled:** GPUI's DirectComposition renderer clashes with `WS_EX_LAYERED`. Remove `WS_EX_LAYERED` and the `SetLayeredWindowAttributes` call, keeping `WS_EX_TRANSPARENT` alone, and re-test rendering and click-through. If neither variant both renders and passes clicks through, revert this task's code, keep Task 2, and **stop and report** what you saw for each variant.

- [ ] **Step 4: Verify the focus and click-through behaviour by eye** (spec verification 4).
  1. Open Notepad and place it so the bottom-centre of the screen is over its text area.
  2. In PCPanel, click "Show overlay in 3s", then click into Notepad and keep typing.
  3. Expected: the overlay appears over Notepad, and typing continues uninterrupted, with no lost keystrokes and the Notepad caret staying active.
  4. While the overlay is visible, click on the part of Notepad beneath it. Expected: the click lands in Notepad and moves the caret.

- [ ] **Step 5: Commit.**

git add crates/pcpanel-gui Cargo.lock
